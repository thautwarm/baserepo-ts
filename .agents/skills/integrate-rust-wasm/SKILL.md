# integrate-rust-wasm

Keep Rust sources in `rust-workspace/` and expose them through an ordinary
`packages/lib*/` TypeScript library. Callers use its `ILibrary`; Wasm stays private.

The working example is [arithmetic](../../../rust-workspace/arithmetic/src/lib.rs),
consumed by [libarithmetic](../../../packages/libarithmetic/src/index.ts). Run it with
`pnpm exec node make.ts test:libarithmetic`; regenerate with
`pnpm exec node make.ts wasm:arithmetic`.

## build-artifact

1. Add the crate to `rust-workspace/Cargo.toml`. Use `cdylib` for Wasm; add `rlib`
   when native Rust consumers or tests need it. Keep release settings at the
   workspace root and commit `Cargo.lock`.
2. Pin the Rust toolchain and include the `wasm32-unknown-unknown` target. This
   target provides no host filesystem or OS-thread implementation.
3. Build from `rust-workspace/`, selecting the crate explicitly:

   ```sh
   cargo rustc -p parser-core --lib --release --target wasm32-unknown-unknown --crate-type cdylib
   ```

   The default output is `target/wasm32-unknown-unknown/release/parser_core.wasm`.
   The explicit crate type builds only the dynamic-library artifact for this run.
4. For size-sensitive packages, run `wasm-opt -Oz` before embedding. Pin the
   optimizer and enable the Wasm features required by the selected Rust toolchain;
   verify the optimized module loads in the intended runtime.
5. Use a Node TypeScript helper to encode the final bytes as a generated module:

   ```ts
   const source = `// Generated; do not edit.\nexport const WASM_BASE64 = ${JSON.stringify(bytes.toString("base64"))};\n`;
   ```

   Write it to `packages/libparser/src/generated/wasm-bytes.ts`. Track this file
   when consumers should run the checked-in package without installing Rust.

## runtime-boundary

- For a small synchronous API, raw scalar exports plus linear memory avoid a
  separate binding generator. Read [raw-wasm-abi](references/raw-wasm-abi.md) when
  implementing strings, structured results, or instance reuse. If the API needs
  generated bindings, include their generator and outputs in the build instead.
- Decode the inline bytes with `atob` and `Uint8Array`, then instantiate once in a
  private runtime module. Embedding requires no runtime file read or fetch.
- Keep Rust layouts, pointers, and Wasm exports out of `types.ts`. The TypeScript
  adapter converts results and errors to the declared library contract.
- Synchronous compilation can be restricted by the host. If initialization must
  be asynchronous, represent readiness in the API. Add a JavaScript fallback only
  when required; distinguish initialization failure from a valid parser error.

## build-integration

Use the [nomake](../nomake/SKILL.md) skill to register the generated bytes module
as a file target. Its inputs include Rust sources and manifests, `Cargo.lock`, the
toolchain file, and build/embedding helpers. Make the TypeScript package's checks
and tests depend on that target. Keep command execution in `scripts/` helpers.
Declare each crate with `rustProject()`; its consuming `tsProject()` depends on it.
These helpers wire generated outputs into checks and propagate dependency tests.

Check a native Rust test and a TypeScript call through the generated module;
native tests alone do not exercise the ABI. Verify a cache hit and regeneration
after a Rust input changes. If two backends exist, run the same contract cases
against both, including errors, limits, and non-ASCII input.

Sources: [Cargo rustc](https://doc.rust-lang.org/cargo/commands/cargo-rustc.html),
[wasm32-unknown-unknown](https://doc.rust-lang.org/rustc/platform-support/wasm32-unknown-unknown.html).
