# write-useful-docs

## before-writing

- 先读目标文件、上级索引和相关约定，确定读者、用途、内容边界及权威来源。
- 为每条信息选择落点，再写句子。已有合适位置就更新；其他文件引用它，避免复制出多份权威内容。生成文档改源文件。
- 只修改本次任务涉及的内容。采用本 skill 不代表授权批量重命名、迁移或重组整个文档目录。

## stable-names

- 文档 title、章节标题、tag 和新增文档的语义名称使用 kebab-case，例如 `runtime-requirements`、`failure-recovery`。不加章节号、流水号或排序前缀。
- 名称表达主题，不编码它在目录或列表中的位置。顺序通过索引、依赖或流程关系表达。
- 标题与文件名保持稳定；确需改名时检查相关链接和引用。kebab-case 本身不能保证改名后引用仍有效。
- 日期、版本、数量和协议标识按实际含义保留；保留 `SKILL.md` 等规定名称及引用对象的原始拼写。journal 文件按日期命名。

## information-home

- 需求写目标、场景、约束与验收；设计写职责、关系与设计选择；参考写接口或配置契约；工作流写执行、验证与回滚步骤。
- 区分现状描述与目标约定。结合需求、决策、实现和测试判断差异是文档过时、实现缺失还是有意偏离；依据不足时标明未知。
- 长期文档保留对读者仍有用的事实、规则、依据与限制。当天进度、待办、阻塞、待确认方案、当次测试结果和机器状态进入工作日志。
- 尚未确定如何组织的信息，先存 `docs/worklogs/journal/<date>.md`。日期从环境取得；项目已有等价 journal 时复用它。
- 整理日志时，把确认后的稳定内容放入对应文档，日志保留当次事实与指向权威内容的链接。
- 当次测试通过不能写成长期保证；技术结论所需的版本、日期、证据与未验证范围应保留。
- 不为填齐模板向文档塞入不属于其职责的栏目。

## information-hierarchy

- 同级条目保持相同的抽象层级和分类维度。目标、职责、实现手段、命令与执行结果分别归位。
- 总体约束放上层，具体规则放所属主题，示例与细节放相应规则之下；只在需要时拆文件。
- 例如：`storage` 与 `scheduling` 可以并列；`scheduling` 与某条重试命令不应并列。重试命令归入相关工作流。
- 一个文件或段落有多个用途时，先判断是否需要拆分或改为引用，再润色措辞。

## privacy

- 共享文档、journal、示例与提交内容使用脱敏或合成数据。路径优先写 `$PROJECT_ROOT`、相对路径或角色名，避免暴露个人目录、真实身份与私人环境信息。
- 任务确需临时保留未脱敏材料时，可放 `$PROJECT_ROOT/tmp/`；只保留必要内容，使用后清理。
- 写入前确认该目录及目标文件不在 Git 跟踪中、被忽略，且不会进入本次发布、附件或生成产物。暂存区、差异与输出也要检查；目录名不提供隐私保证。
- 不把原始私人材料复制进 journal、报告或工具输出。密码、token、私钥等凭据遵循项目已有秘密管理规则，不作为普通临时笔记保存。

## current-reader

- 每句话都应对首次接触项目的读者有用。
- 描述当前契约、约束与理由。变更历史只在解释兼容、迁移或当前限制时保留；其余过程记录进入 journal。
- 直接表达事实或动作。允许短句、祈使句和清楚的片段；避免文学化、修辞、漂亮话与无信息的铺陈。
- 精简时保留否定、范围、版本、单位、默认值、失败条件和其他影响含义的限定词。不要为缩短句子删掉必要概念。

例如：

```text
Use Node 24.6+ and pnpm. Run TypeScript directly; no JavaScript build step or `dist/`.
```

优于：

```text
The project requires Node 24.6+ and pnpm, running TypeScript directly with no build process or dist/ folder.
```

前者直接给出环境与执行约束，并明确排除的是 JavaScript 构建步骤。此处版本仅为写作示例。

## review

- 先检查内容是否应该存在、属于哪里、层级是否一致；再改句子。
- 删除测试：删掉这句话若不损失事实、判断、逻辑或必要动作，就删除整句。
- 追问测试：被问到“具体指什么”“凭什么”时，应能指出事实、依据或推理；否则核查、标明未知或删除。
- 去掉重复规则、过期状态、模板填充、空泛总结与假对立。示例必须帮助判定或操作。
- 核对语义、职责、证据限定、隐私与受影响的引用。排版或 frontmatter 验证通过不代表内容正确。
